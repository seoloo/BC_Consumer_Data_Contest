# 05. 멱등성 · 재현성

## 한 줄 요약

**같은 입력이면 몇 번을 돌려도 같은 결과**가 나오게 만들었습니다. 파일 내용의 지문(SHA-256)으로 "지난번과 같은 파일인가"를 판단하고, 무작위가 들어가는 곳은 시드를 고정했습니다.

- 멱등성(idempotency): 같은 작업을 여러 번 해도 한 번 한 것과 결과가 같은 성질
- 재현성(reproducibility): 다른 날, 다른 PC에서 돌려도 같은 결과가 나오는 성질

## 왜 필요했나

- 배치 작업은 실패하면 다시 돌립니다. 다시 돌릴 때마다 데이터가 두 번 쌓이거나 파일이 바뀌면, 무엇이 진짜인지 알 수 없습니다.
- "원본이 바뀌었나?"를 파일 수정 시각으로 판단하면 틀립니다. 복사만 해도 시각은 바뀌고, 내용이 바뀌어도 시각이 그대로일 수 있습니다.
- 합성 데이터와 테스트는 실행할 때마다 같은 값이 나와야 결과를 비교할 수 있습니다.

## 어떻게 했나

| 곳 | 방법 | 코드 |
|---|---|---|
| Bronze 적재 | 원본과 Bronze 복사본의 SHA-256이 같으면 복사하지 않고 '변경 없음'으로 영수증에 기록 | `medallion.build_bronze()`, `file_fingerprint()` |
| KOSIS 수집 | 응답 행을 정렬해서 저장하고, 내용이 같으면 파일을 다시 쓰지 않음. 받은 시각은 데이터 파일이 아니라 기록 파일에 | `kosis.landing_json()`, `write_if_changed()` |
| 객체 저장소 업로드 | 객체 메타데이터에 SHA-256을 적고, 다음에 같으면 올리지 않음. 받을 때 영수증 지문과 다시 맞춤 | `object_store.upload_if_changed()`, `download_bronze()` |
| PostgreSQL raw 적재 | 원본 지문 · 행 수 · 합계가 지난 적재와 같으면 '변경 없음'. 다르면 한 트랜잭션에서 다시 적재 | `warehouse.Warehouse.load()` |
| 합성 데이터 | 시드 고정 (`numpy.random.default_rng(seed)`), 엑셀 안에 저장되는 시각을 고정 | `synthetic.save_excel()` |
| 분석 결과 | 노트북과 같은 반올림 규칙 유지 (연령 비중을 소수 첫째 자리로 반올림한 뒤 계산) | `card_spending.build_age_spending_structure()` |

- **지문은 1MB씩 나눠 읽어 계산합니다.** 큰 파일도 메모리를 적게 씁니다.
- **'실행마다 바뀌는 값'을 데이터에서 분리했습니다.** 적재 시각, 수집 시각은 영수증 · 기록 파일에만 두고, 데이터 파일 내용에는 넣지 않습니다. 시각이 데이터에 들어가면 같은 내용이어도 지문이 매번 달라집니다.

## 써 보고 확인한 것

- 같은 원본으로 Bronze를 다시 적재하면 모든 파일이 '변경 없음'으로 기록됩니다 (`test_bronze_is_idempotent`).
- **엑셀 파일은 같은 시드로 만들어도 해시가 매번 달랐습니다.** xlsx는 압축 파일이라 안쪽 파일마다 저장 시각이 들어가고, `docProps/core.xml`에도 작성 · 수정 시각이 남기 때문입니다. 저장 시각을 고정한 뒤에는 CSV · 엑셀 모두 같은 시드 → 같은 SHA-256이 됩니다 (`test_same_seed_gives_identical_files`).
- KOSIS 응답을 순서만 바꿔 두 번 저장해도 같은 파일이 되고, 두 번째는 '변경 없음'으로 기록됩니다 (`test_collect_twice_gives_same_file`).
- 객체 저장소에 두 번째 올릴 때 데이터 파일 60개가 모두 '변경 없음'이었고, 저장소를 거쳐도 1초 정도만 더 걸렸습니다 (14 참고).
- 반올림 규칙까지 노트북과 맞췄기 때문에 공모전 결과표 6/6이 소수점까지 그대로 나옵니다.

## 다른 방법과 고르지 않은 이유

| 방법 | 고르지 않은 이유 |
|---|---|
| 파일 수정 시각으로 변경 판단 | 복사 · 압축 해제만 해도 시각이 바뀌어 틀린 판단을 합니다 |
| 파일 크기로 변경 판단 | 숫자 한 자리가 바뀌어도 크기는 같을 수 있습니다 |
| MD5 지문 | 충분히 빠르지만 충돌이 알려진 방식이라, 기록용으로는 SHA-256이 무난합니다 |
| 매번 덮어쓰기 | 결과는 같아도 "언제 내용이 바뀌었는지" 기록이 사라집니다 |

## 앞으로

- Phase 4 Airflow에서 "지난달 다시 돌리기(backfill)"를 할 때 이 성질이 그대로 필요합니다. 같은 달을 두 번 돌려도 데이터가 두 번 쌓이지 않아야 합니다.

## 스스로 점검할 질문

<details><summary>Q1. 멱등성이 왜 데이터 파이프라인에서 중요한가?</summary>

파이프라인은 실패하면 다시 돌리는 것이 기본입니다. 멱등하지 않으면 재실행할 때 중복 적재나 값 변경이 생겨, 재실행 자체가 위험한 작업이 됩니다. 멱등하면 "일단 다시 돌린다"가 안전한 해결책이 됩니다.
</details>

<details><summary>Q2. 같은 시드로 만든 엑셀의 해시가 달랐던 이유와 해결 방법은?</summary>

xlsx는 zip 압축 파일이고, 압축 안의 각 파일에 저장 시각이 기록되며 문서 속성(core.xml)에도 작성 시각이 들어갑니다. 압축 항목의 시각과 core.xml의 시각을 고정된 값으로 바꿔 다시 압축했습니다.
</details>

<details><summary>Q3. 받은 시각을 데이터 파일이 아니라 기록 파일에 따로 두는 이유는?</summary>

시각은 실행할 때마다 바뀌므로 데이터 파일에 넣으면 내용이 같아도 지문이 달라집니다. 그러면 "바뀌었나?"를 판단할 수 없습니다. 시각은 기록(로그)에 쌓고, 데이터 파일은 내용만 담게 했습니다.
</details>
