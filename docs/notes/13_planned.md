# 13. 앞으로 쓸 기술

아직 쓰지 않은 기술을 **왜 쓰려는지**, 쓰고 나서 **무엇을 확인할지** 먼저 적어 둡니다.
쓰고 나면 "써 보고 확인한 것"을 채워 해당 주제의 문서로 옮깁니다.

## Phase 2 · 수집과 저장

### ~~MinIO (Bronze 저장소)~~ → 2026-10-21 SeaweedFS로 완료

MinIO 무료판 이미지가 Docker Hub에서 지워져 같은 S3 API의 SeaweedFS를 썼습니다. 결과는 [14 객체 저장소](14_object_storage.md).

### Docker Compose (시작함)

- **왜:** 저장소, PostgreSQL, Airflow를 각자 설치하면 PC마다 버전 · 설정이 달라집니다. Compose 파일 하나로 같은 환경을 띄우고 지울 수 있습니다.
- **지금:** `docker-compose.yml`에 SeaweedFS(객체 저장소) · PostgreSQL(웨어하우스) 두 개. 버전 고정, 계정은 `local_env`가 `.env`에만 만듦, healthcheck로 준비 확인 (2026-10-21).
- **확인할 것:** PostgreSQL · Airflow를 더한 뒤에도 새 PC에서 `docker compose up -d` 한 번으로 전체가 뜨는지.

## Phase 3 · 데이터 마트와 품질

### ~~PostgreSQL~~ → 2026-10-21 raw 스키마부터 사용 중 ([15](15_postgresql.md)). silver · gold 스키마는 dbt와 함께

- **왜:** Silver · Gold를 SQL로 조회할 수 있어야 대시보드나 다른 도구에서 쓸 수 있습니다. 파일(Parquet)과 달리 여러 사람이 동시에 읽고, 권한을 나누고, 테이블 사이 관계를 제약으로 걸 수 있습니다.
- **확인할 것:** 층 이름이 스키마 이름(silver, gold)이 되는지, 파이썬 결과와 SQL 결과가 같은지.

### dbt + dbt tests → 2026-10-21 Silver · Gold 사용 중 ([16](16_dbt.md))

- **실행 방법 (결정):** Docker 공식 이미지 `ghcr.io/dbt-labs/dbt-postgres:1.9.0`. dbt가 Python 3.14를 아직 지원하지 않을 수 있어, PC에 Python을 더 설치하지 않고 버전을 고정하려고.

- **왜:** 지금 Silver → Gold 계산은 파이썬 함수입니다. dbt로 옮기면 SQL 모델 사이의 의존 관계가 그림(lineage)으로 보이고, 품질 검사(지금의 대사 10개)를 `not_null`, `unique`, `relationships`, 직접 만든 테스트로 선언할 수 있습니다.
- **확인할 것:** 같은 데이터로 dbt 결과와 파이썬 결과가 같은지, 지금의 대사 검사가 dbt tests로 모두 옮겨지는지.

## Phase 4 · 자동화와 화면

### ~~Airflow~~ → 2026-10-21 월 배치 DAG 사용 중 ([18](18_airflow.md))

- **왜:** 매달 새 결제 데이터가 들어온다고 보면, 수집 → Bronze → Silver → Gold → 대사를 순서대로 자동 실행하고, 실패하면 그 단계부터 다시 돌려야 합니다.
- **확인할 것:** 지난 6개월을 다시 돌려도(backfill) 중복 없이 같은 결과인지 (05 멱등성), 대사 실패 시 다음 단계가 멈추는지.

### ~~GitHub Actions~~ → 2026-10-21 CI 사용 중 ([17](17_ci.md))

- **왜:** 코드를 올릴 때마다 테스트를 자동으로 돌려, 깨진 코드가 main에 들어가지 않게 합니다. 합성 데이터 덕분에 원본 없이 CI에서 전체 실행이 가능합니다.
- **확인할 것:** 인증키 없이 테스트가 모두 도는지, 실패하면 PR에서 바로 보이는지.

### Streamlit

- **왜:** 결과를 CSV가 아닌 화면으로 보여 줍니다. 지역 · 업종을 골라 Stress와 4유형을 바로 볼 수 있게 합니다.
- **확인할 것:** Gold 테이블만 읽어서 화면이 만들어지는지 (계산은 파이프라인, 화면은 보여 주기만).

## 일부러 쓰지 않는 것

| 기술 | 쓰지 않는 이유 |
|---|---|
| Kafka (스트리밍) | 데이터가 월 단위로 들어옵니다. 실시간 처리가 필요 없고, 배치로 충분합니다 |
| Spark (분산 처리) | 카드 데이터가 Silver 기준 약 16만 행입니다. pandas 한 대로 몇 초면 끝나는 크기라 분산 처리는 과합니다 |
| 클라우드 관리형 서비스 | 비용과 계정이 필요하고, 다른 사람이 그대로 재현하기 어렵습니다. 로컬 Docker로 같은 구조를 보여 줍니다 |
| 머신러닝 | 이 분석의 핵심은 예측이 아니라 인구 구조에 대한 노출을 재는 지표입니다 |
