# 11. 합성 데이터

## 한 줄 요약

원본 8종과 **파일 이름 · 열 이름 · 인코딩 · 시트 구조가 똑같은** 가짜 데이터를 만듭니다. 숫자는 직접 정한 값이고, 같은 시드면 바이트까지 같은 파일이 나옵니다.

## 왜 필요했나

- 원본은 재배포할 수 없어서, 원본이 없는 사람은 파이프라인을 돌려 볼 방법이 없었습니다.
- 처음 만든 테스트용 가짜 데이터(`tests/synthetic_raw_files.py`)는 형식이 단순해서, 원본에서 실제로 부딪힌 문제(성별 코드 x, 깨진 따옴표, 병합 셀)를 하나도 담지 못했습니다. 그런 데이터로는 정제 코드가 그 문제를 처리하는지 확인할 수 없습니다.
- 나중에 CI(GitHub Actions)에서 테스트를 돌리려면 원본 없이도 전체가 돌아야 합니다.

## 어떻게 했나

- 코드: `src/future_stress/synthetic.py`
- 실행: `python -m future_stress.synthetic` (생성만), `python -m future_stress.pipeline --synthetic` (생성 + 전체 실행)
- 결과는 `data/synthetic/` 아래(raw · bronze · silver · gold · output)에 따로 만들어 원본 결과와 섞이지 않게 했습니다.

**원본과 같게 만든 것**

| 원본의 특징 | 합성 데이터 |
|---|---|
| 개인이 아닌 결제 | 성별 코드 3, 성별 · 연령 x 행 (금액의 약 12%) |
| 업종명 안 공백 | `편 의 점`, `슈퍼 마켓`, `제 과 점` |
| 6개월이 다 없는 지역 × 업종 | 약 3%에서 한 달을 뺌 |
| 경기는 일반구 단위 | `수원시 장안구` 등 |
| 주민등록인구 cp949 · 쉼표 숫자 · 행정코드 | 같은 형식 |
| 서울 장래인구 5세 · 1세 · 합계 혼재, `90~94세` · `95세 이상` | 같은 형식 (그래서 90세 이상 누락도 원본과 똑같이 재현) |
| 부산 · 경기 장래인구 병합 셀, `0 - 4세` | 블록 첫 행에만 시군구 · 성별 |
| 부산 생활인구 2025년이 아닌 행 | 2024년 12월 행 |
| 경기 유동인구 파일명 `연천시` 오타 | 같은 이름 |

**원본과 다른 것: 모든 숫자.** 업종별 연령 구성, 매출 규모, 인구 피라미드, 연령별 인구 증감 방향은 업종 · 인구 구조를 생각해 직접 정했습니다. 원본에서 계산한 값은 하나도 쓰지 않았습니다.

**어떻게 '그럴듯하게' 만들었나**

- 연령 구성: 업종별 기본 구성을 중심으로 지역마다 조금씩 다르게 뽑았습니다 (디리클레 분포).
- 월별 매출: 추세(평균 −0.3%, 표준편차 1.5%)와 잡음을 곱해 성장하는 곳과 아닌 곳이 섞이게 했습니다.
- 장래인구: 젊을수록 줄고 나이 들수록 느는 방향을 기본으로, 지역마다 ±6%p 차이를 뒀습니다.
- 다른 인구 파일(주민등록, 생활인구)은 장래인구의 2026년 값을 기준으로 만들어 서로 어긋나지 않게 했습니다.

## 써 보고 확인한 것

- 합성 데이터로 Bronze → Silver → Gold → 대사 10개가 **모두 통과**합니다 (179,702 − 66,206 = 113,496행). 결과 표도 모두 값이 채워집니다.
- 생성 약 10초, 파이프라인 약 9초라 테스트에서 매번 돌릴 수 있습니다.
- **같은 시드 → 같은 SHA-256.** 처음에는 엑셀 3개의 해시가 매번 달랐습니다. xlsx 안에 저장 시각이 기록되기 때문이었고, 시각을 고정해서 해결했습니다 (05 참고).
- 예전 테스트용 가짜 데이터를 지우고 전체 실행 테스트를 이 생성기로 바꿨습니다. 생성기가 하나뿐이라 관리할 곳도 하나입니다.
- 원본 결과는 여전히 발표 결과와 6/6 일치합니다 (합성 데이터 작업이 원본 처리에 영향을 주지 않음).

## 다른 방법과 고르지 않은 이유

| 방법 | 고르지 않은 이유 |
|---|---|
| Faker 라이브러리 | 이름 · 주소 같은 가짜 개인정보에 강한 도구입니다. 여기서는 숫자 분포와 파일 형식이 필요했습니다 |
| 원본 분포를 학습해서 생성 (SDV 등) | 원본에서 학습하면 원본 정보가 합성 데이터에 섞여 나갈 수 있습니다. 공개용이라 원본을 쓰지 않는 쪽을 골랐습니다 |
| 원본을 섞어서(셔플) 공개 | 값 자체는 원본 그대로라 재배포에 해당합니다 |

## 스스로 점검할 질문

<details><summary>Q1. 합성 데이터에 원본의 '지저분한 점'까지 넣은 이유는?</summary>

정제 코드가 처리해야 할 상황이 합성 데이터에 없으면, 그 코드가 동작하는지 원본 없이는 확인할 수 없습니다. 깨끗한 가짜 데이터로는 테스트가 통과해도 실제 원본에서 실패할 수 있습니다.
</details>

<details><summary>Q2. 합성 데이터 결과가 발표 결과와 다른데, 그럼 무엇을 확인하는 건가?</summary>

계산 결과의 숫자가 아니라 파이프라인이 끝까지 돌아가는지, 층 사이 숫자가 맞는지, 결과 표의 모양이 같은지를 확인합니다. 숫자가 맞는지는 원본이 있는 곳에서 `--compare`로 따로 확인합니다.
</details>

<details><summary>Q3. 원본 분포를 학습해서 더 비슷하게 만들지 않은 이유는?</summary>

원본에서 학습한 값이 합성 데이터에 들어가면 원본 정보가 새어 나갈 수 있습니다. 이 데이터는 공개용이라, 원본을 전혀 보지 않고 직접 정한 값만 쓰는 쪽이 안전합니다.
</details>
