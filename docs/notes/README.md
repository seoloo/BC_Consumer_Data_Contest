# 기술 · 설계 기록

이 프로젝트에서 쓴 기술과 설계를 **왜 골랐고, 써 보니 무엇이 좋아졌는지** 적어 두는 곳입니다.
작업이 하나 끝날 때마다 해당 주제에 내용을 덧붙입니다.

## 읽는 법

모든 주제는 같은 순서로 적었습니다.

1. **한 줄 요약**
2. **왜 필요했나**: 이 프로젝트에서 실제로 겪은 문제
3. **어떻게 했나**: 코드 위치와 핵심 아이디어
4. **써 보고 확인한 것**: 이 프로젝트에서 나온 숫자와 결과
5. **다른 방법과 고르지 않은 이유**
6. **스스로 점검할 질문**: 답은 접어 두었습니다. 먼저 답해 보고 펼쳐서 확인합니다.

주제마다 맨 위에 **결정 기록**(날짜 · 결정 · 이유)을 둡니다.

## 한눈에 보는 흐름

```text
원본 8종 (BC카드 · 인구 · 생활/유동인구)          ← 07 지저분한 원본, 10 비공개, 11 합성 데이터, 09 API 수집
   │
   ▼
Bronze   원본 그대로 + 지문(SHA-256) 영수증         ← 03 메달리온, 05 멱등성
         SeaweedFS 버킷에 올리고 받아 지문 확인       ← 14 객체 저장소
         PostgreSQL raw 스키마에 표기 그대로 적재      ← 15 PostgreSQL
         dbt가 raw → silver → gold 스키마 (SQL 모델 · 테스트) ← 16 dbt
   │
   ▼
Silver   정제 · 표준화한 표 (Parquet 6개)           ← 06 Parquet, 07 원본 다루기
   │
   ▼
Gold     Stress · 4유형 · 검증 · 전략 (Parquet 16개) ← 01 코드 구조
   │
   ▼
대사     층 사이 숫자 확인 10개, 실패하면 멈춤        ← 04 품질 검사, 08 예외 처리
   │
   ▼
output/  발표 결과와 같은 형식의 CSV (6/6 일치)      ← 02 테스트

매달 1일 위 순서를 Airflow DAG가 돌림                ← 18 Airflow
gold 스키마를 읽기 전용으로 읽어 화면에 보여 줌       ← 19 대시보드
전체 상태 한 번에 보기 · 실패했을 때 할 일          ← 20 운영 (../operations.md)
```
