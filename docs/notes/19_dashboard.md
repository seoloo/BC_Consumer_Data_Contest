# 19. Streamlit 대시보드

## 한 줄 요약

PostgreSQL `gold` 스키마(dbt 결과)만 **읽기 전용**으로 읽어, 지역 · 업종별 Future Stress와 4유형을 고르고 눌러 볼 수 있는 화면을 만들었습니다. 화면은 계산하지 않고 보여 주기만 합니다. 그래서 대신 화면에 뜬 숫자가 gold 표와 같은지를 화면 안에서 한 번 더 맞춰 봅니다.

## 왜 필요했나

- 지금까지 결과는 CSV와 DB 표였습니다. '서울 성동구 편의점은 왜 취약한가'를 보려면 SQL을 직접 써야 했습니다.
- 숫자를 보는 사람은 대부분 SQL을 쓰지 않습니다. 고르고 눌러서 볼 수 있어야 결과가 쓰입니다.
- 화면이 생기면 '화면에 보이는 숫자가 맞나'가 새 질문이 됩니다. 그래서 화면이 계산을 하지 않게 하고, 화면 안에 맞춰 보기를 넣었습니다.

## 어떻게 했나

```text
PostgreSQL gold (dbt) ──읽기 전용──▶ dashboard_data.py ──▶ dashboard/app.py (Streamlit)
  gold_future_stress                 GoldReader.read()          개요 · 지역 · 업종 순위
  gold_age_stress                    stress_ranking()           4유형 지도 · 한 건 자세히
  gold_market_type                   type_counts() · counts_match()
  gold_market_type_counts            age_breakdown() · contributions_add_up()
```

| 탭 | 보여 주는 것 | 읽는 표 |
|---|---|---|
| 개요 | 분석 대상 수, 2040년 취약 건수, 착시성장형 수, 4유형 × 지역 건수, raw 적재 기록 | `gold_market_type`, `gold_market_type_counts`, `raw._load_log` |
| 지역 · 업종 순위 | 지역 · 업종 · 순서 · 건수를 골라 Stress 막대 (빨강 취약 · 파랑 안정) | `gold_future_stress` |
| 4유형 지도 | 가로 = 1월 대비 6월 증감률(지금), 세로 = Stress 2040(미래), 색 = 취약 / 안정, 모양 = 성장 / 비성장 | `gold_market_type` |
| 한 건 자세히 | 연령대별 ① 이용금액 비중 ② 인구 증감률 ③ 기여도 = ① ÷ 100 × ② | `gold_age_stress`, `gold_future_stress` |

**화면 안에서 맞춰 보는 것 두 가지**

- 화면에서 센 4유형 건수 = dbt가 만든 `gold_market_type_counts`
- 한 건의 연령대 기여도 6개를 더한 값 = 그 건의 Future Stress

맞으면 '✓ 같습니다'라고 보여 주고, 다르면 경고를 띄웁니다.

**그 밖에**

- 5분 동안은 DB를 다시 읽지 않습니다 (`st.cache_data(ttl=300)`, '새로 읽기' 버튼으로 비움).
- DB가 꺼져 있거나 표가 없으면 오류 화면 대신 '무엇을 하면 되는지'를 보여 줍니다 (`connection_problem()`).
- 주소로 처음 화면을 정할 수 있습니다: `/?data=synthetic&tab=types`. 캡처 스크립트(`dashboard/capture.py`)가 이걸로 탭마다 찍습니다.

| 실제 DB 테스트 | 합성 gold 792건 모두 기여도 합 = Stress, 건수 일치, **쓰기를 시도하면 `ReadOnlySqlTransaction`으로 막힘** |

**부딪힌 것**

1. **Chrome 명령 한 줄(`--screenshot`)로 캡처하면 빈 화면이 찍혔습니다.** 흐름도는 이 방법으로 찍지만, Streamlit은 페이지가 열린 뒤 웹소켓으로 데이터를 받아 그려서 기다리지 않으면 빈 화면입니다. 화면이 다 그려질 때까지 기다릴 수 있는 Playwright를 캡처에만 씁니다(이 PC의 Chrome 사용, 브라우저를 따로 받지 않음).
2. **숫자 카드에 '↑ 취약'처럼 화살표가 붙었습니다.** Streamlit의 증감 표시가 기본으로 화살표를 붙여서 '취약이 올랐다'처럼 읽혔습니다. `delta_arrow="off"`로 껐습니다.

## 다른 방법과 고르지 않은 이유

| 방법 | 고르지 않은 이유 |
|---|---|
| Superset · Metabase (BI 도구) | 컨테이너 · 설정 · 계정 관리가 무겁습니다. '한 건 자세히'처럼 정해진 흐름을 보여 주기엔 코드로 짜는 쪽이 간단합니다 |
| Tableau · Power BI | 유료이고, 다른 사람이 저장소만으로 똑같이 띄울 수 없습니다 |
| Dash · FastAPI + 프런트엔드 | 더 자유롭지만 코드가 몇 배로 늘어납니다. 이번 목표는 파이프라인 결과를 보여 주는 것까지입니다 |
| 화면에서 직접 계산 | 같은 계산이 파이프라인 · dbt · 화면 세 군데에 생깁니다. 화면은 gold만 읽고 맞춰 보기만 합니다 |
| 대시보드 전용 DB 계정 | 가장 안전하지만, dbt가 표를 다시 만들 때마다 권한을 다시 줘야 해서 dbt `grants` 설정이 함께 필요합니다. 이번에는 읽기 전용 트랜잭션으로 막고, 전용 계정은 [13](13_planned.md)에 남깁니다 |

## 스스로 점검할 질문

<details><summary>Q1. 화면이 계산을 하지 않게 한 이유는?</summary>

계산이 여러 곳에 있으면 숫자가 서로 달라질 수 있습니다. 이 프로젝트는 파이썬과 dbt의 결과가 같은지를 이미 한 칸씩 비교하므로, 화면은 그 결과(gold)만 읽어야 '화면 숫자 = 검사를 통과한 숫자'가 됩니다.
</details>

<details><summary>Q2. 읽기 전용 연결은 무엇을 막아 주나?</summary>

연결을 `BEGIN READ ONLY`로 열어서, 화면 코드에 실수가 있어도 INSERT · UPDATE · CREATE가 DB에서 거절됩니다(테스트로 확인). 다만 같은 계정이라 마음먹고 바꾸면 풀 수 있습니다. 완전히 막으려면 SELECT 권한만 있는 전용 계정이 필요합니다.
</details>

<details><summary>Q3. 4유형을 색 네 개로 칠하지 않은 이유는?</summary>

점그림에서는 모든 색 쌍이 서로 구분돼야 하는데, 4가지 색이면 색약인 사람에게 겹쳐 보이는 쌍이 생깁니다. 4유형은 '미래 취약 / 안정' × '현재 성장 / 비성장'의 조합이라, 색 2개와 모양 2개로 나눠 그리면 색만으로 구분하지 않아도 됩니다.
</details>

<details><summary>Q4. 화면 테스트는 어떻게 했나?</summary>

Streamlit `AppTest`로 브라우저 없이 앱을 실행하고, DB를 읽는 부분만 가짜 데이터로 바꿔 넣었습니다(`monkeypatch`). 탭 이름, 숫자 카드 값, 합성 전환, DB가 꺼졌을 때의 안내를 확인합니다. 실제 DB로는 합성 gold를 읽어 같은 맞춰 보기를 전체 건에 돌립니다.
</details>
