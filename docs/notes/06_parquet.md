# 06. 저장 형식 Parquet

## 한 줄 요약

Silver · Gold 표를 CSV 대신 Parquet(pyarrow)으로 저장합니다. 열마다 타입이 저장돼서 다시 읽어도 바뀌지 않고, 압축 덕분에 크기도 많이 줄었습니다.

## 왜 필요했나

- **CSV는 다시 읽을 때 타입이 바뀝니다.** '01' 같은 코드가 숫자 1이 되고, 'x'가 섞인 코드 열은 파일마다 타입이 달라지는 식입니다. 단계마다 `dtype=`을 붙여 읽어야 했습니다.
- **인코딩이 섞였습니다.** 공공기관 CSV는 cp949, 직접 저장한 CSV는 utf-8이라 읽을 때마다 인코딩을 맞춰야 했고, 실제로 글자가 깨진 적이 있습니다.
- 중간 결과를 CSV로 쌓다 보니 `data/processed/`에 파일이 30개 넘게 생겼고 용량도 컸습니다.

## 어떻게 했나

- 코드: `io_utils.save_parquet()`, `io_utils.read_parquet()`
- Silver 6개, Gold 16개를 모두 Parquet으로 저장합니다. 사람이 엑셀로 열어 볼 최종 결과만 `output/`에 CSV(utf-8-sig)로 내보냅니다.
- **한 열에 숫자와 문자가 섞여 있으면 Parquet이 저장에 실패합니다.** 예를 들어 대표 사례 표의 '전환 후' 열에는 `-14.85`와 `'-'`가 함께 있습니다. 이런 열만 골라 문자로 바꿔 저장하게 했습니다.
- CSV를 남긴 곳: 사람이 엑셀로 바로 여는 `output/` 결과. utf-8-sig로 저장해서 엑셀에서 한글이 깨지지 않습니다.

## 써 보고 확인한 것

- 카드 결제 Silver: **CSV 16.4MB → Parquet 1.4MB** (약 1/12).
- 다시 읽어도 열 타입이 그대로라, Gold에서 읽을 때 `dtype` 지정이 필요 없어졌습니다.
- 발표 결과 6/6이 Parquet을 거친 뒤에도 그대로였습니다. 저장 · 읽기 과정에서 값이 바뀌지 않았다는 뜻입니다.

## 다른 방법과 고르지 않은 이유

| 방법 | 고르지 않은 이유 |
|---|---|
| CSV 유지 | 타입 · 인코딩 문제가 그대로 남습니다 |
| pickle | 파이썬 버전 · pandas 버전이 바뀌면 못 읽을 수 있고, 다른 도구(SQL, dbt)에서 쓸 수 없습니다 |
| Excel | 느리고 행 수 제한(약 104만 행)이 있습니다 |
| 바로 데이터베이스 | Phase 3에서 PostgreSQL로 옮길 예정입니다. 지금은 설치 없이 돌아가는 파일 형식이 먼저였습니다 |

## 스스로 점검할 질문

<details><summary>Q1. Parquet이 CSV보다 작은 이유는?</summary>

열 단위로 저장해서 같은 열 안의 비슷한 값(같은 지역명, 같은 업종명)이 모여 있고, 그래서 압축이 잘 됩니다. 타입 정보가 있어 숫자를 글자로 적지 않아도 되는 것도 이유입니다.
</details>

<details><summary>Q2. 숫자와 문자가 섞인 열은 왜 문제가 되고 어떻게 처리했나?</summary>

Parquet은 열마다 하나의 타입을 정해야 하는데, 숫자와 '-' 같은 문자가 섞이면 타입을 정할 수 없어 저장에 실패합니다. 저장 직전에 값의 타입이 둘 이상인 열만 찾아 문자로 바꿨습니다.
</details>

<details><summary>Q3. 그럼 왜 output/에는 CSV를 남겼나?</summary>

output/은 사람이 엑셀로 바로 열어 보는 결과물이고, 발표 결과(contest/results/*.csv)와 같은 형식으로 비교하기 위해서입니다. 파이프라인 안쪽(Silver · Gold)은 Parquet, 사람에게 보여 주는 바깥쪽은 CSV로 나눴습니다.
</details>
