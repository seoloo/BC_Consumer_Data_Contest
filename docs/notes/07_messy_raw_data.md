# 07. 지저분한 원본 다루기

## 한 줄 요약

원본 8종은 제공 기관도 형식도 제각각이었습니다. 문제를 하나씩 확인해서 **처리 규칙을 코드와 주석에 남기고**, 같은 문제를 합성 데이터에도 넣어 계속 확인되게 했습니다.

## 왜 필요했나

실제 데이터는 분석하기 좋은 모양으로 오지 않습니다. 노트북에서는 이런 문제를 셀마다 그때그때 고쳐서, 어떤 문제가 있었고 어떻게 처리했는지가 흩어져 있었습니다.

## 만난 문제와 처리

| 원본 | 문제 | 처리 | 코드 |
|---|---|---|---|
| 여러 CSV | utf-8과 cp949가 섞임 | utf-8-sig로 먼저 읽고, 실패하면 cp949로 다시 읽기 | `io_utils.read_csv_with_encoding_fallback()` |
| BC카드 | 성별 코드 `3` · `x`, 연령 코드 `x`가 행의 약 34% | 개인 결제(성별 1·2, 연령 1~6)만 남기고, 뺀 양을 대사로 확인 | `card_spending.clean_card_spending()` |
| BC카드 | 코드에 `x`가 섞여 숫자로 읽으면 열 타입이 흔들림 | 성별 · 연령 코드를 문자열로 고정해서 읽기 | `card_spending.load_card_spending()` |
| BC카드 | 업종명 안 공백 (`편 의 점`, `제 과 점`) | 공백을 모두 지워 같은 업종이 따로 집계되지 않게 | `clean_card_spending()` |
| BC카드 | 경기는 일반구 단위(`수원시 장안구`), 인구는 시 단위 | 일반구를 상위 시로 합침. 합치기 전후 금액 대사 | `regions.to_parent_city()` |
| 주민등록인구 | 열 이름에 월이 붙음(`2026년01월_계_0~9세`), 숫자에 쉼표, 지역명 뒤 행정코드 | 정규식으로 월 · 행정코드 떼기, 쉼표 숫자 변환, 기준년월은 파일명에서 | `population.load_resident_population()` |
| 주민등록인구 | 세종시는 하위 시군구가 없어 빈칸 | 시도 이름을 시군구로 사용 | 같은 함수 |
| 서울 장래인구 CSV | 9,048번째 줄쯤 닫히지 않은 따옴표 → `pandas.read_csv`가 멈춤 | 더 너그러운 파이썬 `csv` 모듈로 읽기 | `population.load_seoul_future_population()` |
| 서울 장래인구 CSV | 5세 구간 · 1세 · 합계 행이 섞임 | 5세 구간 행만 골라 두 번 세지 않기 | 같은 함수 |
| 부산 · 경기 장래인구 엑셀 | 병합 셀이라 시군구 · 성별이 블록 첫 행에만 있음 | 위의 값을 아래로 채우기(`ffill`) | `population.load_kosis_future_population()` |
| 부산 생활인구 | 2025년이 아닌 행이 섞임, 나이대 이름이 `20대미만` | 기준년월로 거르기, 별칭을 표준 이름으로 | `population.load_busan_living_exposure()` |
| 경기 유동인구 | 시군 × 월마다 파일이 따로 (48개), 파일명 `연천시` 오타 | 폴더째 읽어 합치기, 오타 보정표 | `population.load_gyeonggi_floating_population_shares()`, `regions.fix_region_name()` |
| 연령 표기 전체 | `0~4세`, `0 - 4세`, `95세 이상`, `100세이상` 등 | 시작 나이만 뽑아 6개 연령대로 (`이상`은 60대이상) | `age_groups.age_group_from_label()` |

## 써 보고 확인한 것

- **서울 장래인구의 90세 이상이 빠지고 있었습니다.** 노트북의 5세 구간 목록에는 원본에 없는 `90세 이상`이 들어 있고, 원본에 실제로 있는 `90~94세` · `95세 이상`은 없었습니다. 발표 결과 재현을 위해 지금은 그대로 두고 주석과 리팩토링 노트에 남겼습니다. 원본을 직접 다시 확인하면서 찾은 문제입니다.
- 개인이 아닌 결제가 금액 기준 13.6%라는 것을 대사로 처음 숫자로 확인했습니다.
- 이 문제들을 합성 데이터에도 똑같이 넣었습니다 (11 참고). 처리 코드가 나중에 바뀌어도 합성 데이터 테스트가 다시 확인해 줍니다.

## 다른 방법과 고르지 않은 이유

| 방법 | 고르지 않은 이유 |
|---|---|
| 원본을 손으로 고쳐 저장 | 고친 기록이 남지 않고, 다음 달 원본에 같은 작업을 반복해야 합니다 |
| 문제 행을 그냥 버리기 | 얼마나 버렸는지 모르면 결과를 믿을 수 없습니다. 뺀 양은 반드시 숫자로 남깁니다 |
| 인코딩 자동 추측 라이브러리 (chardet) | 후보가 utf-8과 cp949 둘뿐이라 차례로 시도하는 편이 빠르고 확실합니다 |

## 스스로 점검할 질문

<details><summary>Q1. 성별 · 연령 코드를 문자열로 읽은 이유는?</summary>

코드에 'x'가 섞여 있어 숫자로 읽으면 pandas가 열 전체를 다른 타입으로 바꾸거나, 파일마다 타입이 달라질 수 있습니다. 문자열로 고정하면 '1', '2' 비교가 항상 같게 동작합니다.
</details>

<details><summary>Q2. 서울 90세 이상 누락을 고치지 않고 둔 이유는?</summary>

이번 작업의 목표가 "구조는 바꾸되 발표 결과는 그대로"였기 때문입니다. 고치면 발표 결과와 숫자가 달라지므로, 문제를 기록해 두고 결과를 바꾸는 개선은 따로 하기로 했습니다. 60대이상 비중에 영향을 주는 문제라 개선 후보로 남겼습니다.
</details>

<details><summary>Q3. 병합 셀 엑셀은 어떻게 읽었나?</summary>

병합 셀은 첫 행에만 값이 있고 나머지는 빈칸으로 읽힙니다. 시군구 · 성별 열에 ffill()을 써서 위의 값을 아래로 채운 뒤, '소계' 행(5세 구간)만 골랐습니다.
</details>
