# 09. API 수집 · 재시도

## 한 줄 요약

외부 API(NAVER 데이터랩, KOSIS)는 **클라이언트 클래스 하나**로 감싸고, 일시적인 오류는 점점 길게 기다리며 다시 시도합니다. KOSIS는 받은 응답을 손대지 않고 저장하고, 언제 받았는지 기록을 쌓습니다.

## 결정 기록

| 날짜 | 결정 | 이유 · 사용자 말 |
|---|---|---|
| 2026-10-21 | 서울 · 경기만 KOSIS API로 | KOSIS 검색으로 통계표를 직접 찾음. 부산 구군별 자료는 KOSIS에 없음 |
| 2026-10-21 | 받은 응답을 가공 없이 저장 | Bronze 원칙과 같음. 가공 규칙이 틀려도 다시 받지 않게 |
| 2026-10-21 | 인증키는 다른 프로젝트 `.env`를 `--env-file`로 가리킴 | 사용자 "원격 제어 중이라 pc에 넣을 수 없거든" → 키를 복사하지 않고 가리키기만. 실제 호출 확인은 키를 넣은 뒤 |
| 2026-10-21 | 시도 합계 행은 빼지 않고 이름을 맞춰 비교 | 사용자 "kosis api key 넣었어 확인해줘" → 첫 비교에서 합계 행 이름 차이(API '서울' vs 파일 '합계')로 80칸 불일치. 합계 값까지 확인하려고 `(시도 합계)`로 통일 |

## 왜 필요했나

- **NAVER:** 같은 호출 함수가 노트북에서 5번 넘게 복사 · 수정돼 있었습니다. 호출 제한(429)에 걸리면 그대로 멈췄습니다.
- **KOSIS:** 공모전 때는 장래인구를 사이트에서 손으로 내려받았습니다. 언제, 어떤 조건으로 받았는지 기록이 없고, 다시 받을 때 같은 조건인지 알 수 없었습니다.

## 어떻게 했나

### 클라이언트 클래스

| | NAVER | KOSIS |
|---|---|---|
| 코드 | `naver_datalab.NaverDataLabClient` | `kosis.KosisClient` |
| 인증 | 환경변수 `NAVER_CLIENT_ID` · `NAVER_CLIENT_SECRET` | 환경변수 또는 `.env`의 `KOSIS_API_KEY` |
| 연결 | `requests.Session` 재사용 (같은 서버에 여러 번 요청할 때 빠름) | 같음. 테스트에서는 가짜 세션을 넘김 |
| 시간 제한 | 10초 | 30초 |

### 재시도 (지수 백오프)

```text
1번째 시도 → 실패(일시적) → 2초 대기 → 2번째 시도 → 실패 → 4초 대기 → 3번째 시도 → 실패면 멈춤
```

- 다시 시도하는 경우: 연결 끊김, 타임아웃, HTTP 429 · 500 · 502 · 503 · 504, KOSIS 서버 오류 코드
- 바로 멈추는 경우: 인증키 · 요청변수 오류, 하루 호출 한도 (08 예외 처리 참고)
- 대기 시간을 두 배씩 늘리는 이유: 호출 제한에 걸렸을 때 바로 다시 보내면 또 막히고, 서버가 바쁠 때 계속 두드리면 상황을 더 나쁘게 만듭니다.

### KOSIS 수집 설계

| 결정 | 이유 |
|---|---|
| 서울 · 경기만 API로 받음 | 부산 구군별 장래인구(2015~2040)는 부산시가 따로 낸 자료라 KOSIS에 없음. 파일을 계속 씀 |
| 연도별로 나눠 요청 | KOSIS는 한 번에 받을 수 있는 양에 제한이 있음. 필요한 연도(2026 · 2030 · 2035 · 2040)만 하나씩 |
| 분류 · 항목을 모두 'ALL'로 받음 | 어떤 값을 쓸지는 받은 뒤에 고름. 기준이 바뀌어도 다시 받지 않아도 됨 |
| 응답을 그대로 JSON으로 저장 (`data/raw/kosis/<통계표>/<연도>.json`) | Bronze 원칙과 같음. 가공 전 원본이 있어야 나중에 다시 처리할 수 있음 |
| 행을 정렬해서 저장, 내용이 같으면 다시 쓰지 않음 | 두 번 받아도 같은 파일 (05 멱등성) |
| 받은 기록은 `_collect_log.jsonl`에 한 줄씩 덧붙임 | 언제 받았고 그때 내용이 바뀌었는지가 계속 남음 |
| 지역 · 성별 · 연령이 몇 번째 분류인지 값의 모양으로 찾음 | 통계표마다 분류 순서가 다를 수 있음. 순서를 가정하면 다른 표에서 조용히 틀림 |
| 받은 값과 예전에 내려받은 파일 값을 한 칸씩 비교 (`compare`) | 같다면 파일 대신 API를 원본으로 써도 분석 결과가 바뀌지 않는다는 근거가 됨 |

## 써 보고 확인한 것

- 가짜 응답으로 확인한 것: 연결 끊김 → 503 → 성공이면 결과를 받음, 인증키 만료면 한 번만 요청하고 멈춤, 같은 응답을 순서만 바꿔 두 번 받아도 같은 파일, 분류 순서가 섞여 있어도 지역 · 성별 · 연령을 찾음, 한 칸만 달라도 비교가 '불일치'를 냄 (`test_kosis.py`, 8개)
- 통계표 ID는 KOSIS 검색에서 직접 찾았습니다. 경기 표는 예전 엑셀 파일의 시트 4개(연령별 · 주요연령계층별 · 주요인구지표 · 인구변동요인)와 구성이 같아 같은 통계임을 확인했습니다.
**실제 KOSIS 호출 (2026-10-21, 인증키를 넣은 뒤)**

| 확인 | 결과 |
|---|---|
| 'ALL' 요청 | 서버가 그대로 받아 줌. 오류 · 재시도 없이 8번 요청 모두 성공 |
| 받은 양 | 서울 연도마다 9,048행, 경기 11,136행 (4개 연도 × 2개 표, 약 58MB) |
| 분류 순서 | 둘 다 C1 = 지역, C2 = 성별, C3 = 연령 (값의 모양으로 찾은 결과) · 항목 '추계인구' 하나 · 단위 '명' |
| 파일과 비교 | **서울 2,080칸 · 경기 2,560칸 모두 같음** (시도 합계 포함, 다른 칸 0) |
| 두 번째 받기 | 8개 파일 모두 '변경 없음' (`_collect_log.jsonl`에 두 번 기록) |

- **처음 비교는 '불일치'였습니다.** 값이 다른 칸은 0개였지만, API에만 있는 칸이 서울 · 경기 각 80개였습니다. 80 = 연령 구간 20개 × 연도 4개라서 지역 하나가 더 있다는 뜻이었고, 확인해 보니 **시도 합계 행의 이름이 원본마다 달랐습니다**(API '서울' · '경기', 서울 CSV '합계', 경기 엑셀 '경기도'). 코드는 '서울특별시' · '경기도'만 합계로 알아보고 빼서, API의 '서울' 행이 남았습니다.
- 합계 행을 빼는 대신 양쪽 모두 `(시도 합계)`라는 같은 이름으로 맞췄습니다 (`kosis.label_province_total()`). 그래서 시도 합계 값까지 비교됐고, 결과는 모두 같았습니다.
- **결론:** 서울 · 경기 장래인구는 API 값이 예전에 사이트에서 내려받은 파일과 칸 하나까지 같습니다. 파일 대신 API를 원본으로 써도 분석 결과가 바뀌지 않습니다.

## 다른 방법과 고르지 않은 이유

| 방법 | 고르지 않은 이유 |
|---|---|
| 계속 손으로 내려받기 | 매달 반복하기 어렵고, 받은 조건과 시각이 기록되지 않습니다 |
| 받자마자 가공해서 저장 | 가공 규칙이 틀렸을 때 다시 받아야 합니다. 원본 응답을 남기면 가공만 다시 하면 됩니다 |
| tenacity 같은 재시도 라이브러리 | 재시도 규칙이 단순해서 반복문 10줄이면 됩니다. 의존성을 늘리지 않았습니다 |
| 실제 서버로 테스트 | 인증키 · 서버 상태 · 호출 한도에 따라 결과가 바뀝니다 |

## 스스로 점검할 질문

<details><summary>Q1. 지수 백오프란? 왜 대기 시간을 두 배씩 늘리나?</summary>

실패할 때마다 다음 시도까지의 대기 시간을 두 배로 늘리는 재시도 방식입니다. 일시적인 문제는 짧게 기다려 빨리 회복하고, 문제가 길어지면 서버에 부담을 덜 주면서 기다립니다.
</details>

<details><summary>Q2. API 응답을 가공하지 않고 그대로 저장하는 이유는?</summary>

가공 규칙은 바뀌거나 틀릴 수 있습니다. 원본 응답이 있으면 다시 받지 않고 가공만 다시 하면 되고, 문제가 생겼을 때 "서버가 이렇게 줬는지, 내가 이렇게 바꿨는지"를 나눠 볼 수 있습니다. 메달리온의 Bronze와 같은 생각입니다.
</details>

<details><summary>Q3. KOSIS 응답에서 분류 순서를 가정하지 않은 이유는?</summary>

통계표마다 분류1 · 분류2 · 분류3이 지역 · 성별 · 연령 중 무엇인지 다를 수 있습니다. 순서를 가정하면 다른 표에서 지역을 연령으로 읽는 실수가 오류 없이 일어납니다. 값의 모양(계 · 남자 · 여자면 성별, '세'가 많으면 연령)으로 찾고, 셋을 다 찾지 못하면 멈추게 했습니다.
</details>
