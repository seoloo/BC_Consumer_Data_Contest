목표와 쓰는 기술

공모전 때 노트북으로 한 분석(01~05)을 매달 알아서 돌아가는 파이프라인으로 다시 만들고 있습니다.
기술은 이 데이터에 맞는 것으로 골랐고, 고른 이유와 일부러 쓰지 않은 기술을 함께 적었습니다.

src/future_stress
2026.10 기준
최종 목표

공모전 카드 소비 분석을
매달 같은 결과가 나오는 데이터 마트로

공모전 때 가장 힘들었던 건 분석보다 데이터였습니다.
파일마다 형식이 달랐고, 다시 돌렸을 때 결과가 맞는지 확신하기 어려웠습니다. 이 문제를 푸는 게 이번 목표입니다.

완성되면 이렇게 돌아갑니다
  1. docker compose up 한 번으로 DB, 저장소, Airflow, 대시보드가 함께 실행
  2. Airflow가 매달 데이터를 받아 원본 그대로 보관
  3. dbt가 Bronze → Silver → Gold로 정리하면서 층마다 숫자를 맞춰 봄
  4. 검사를 통과하면 대시보드에 반영, 틀리면 알림
  5. 코드를 올리면 GitHub Actions가 가짜 데이터로 처음부터 끝까지 실행

정합성원본 합계와 결과 합계가 맞는지 매번 확인
자동화매달 실행, 지난 달 다시 돌리기, 실패하면 재시도

처리 로직
Phase 1 · 사용 중		 Python, pandasNumPy, SciPy 공모전 분석이 이미 pandas로 되어 있고, 원본으로 돌려서 발표 숫자 6개가 그대로 나오는 것까지 확인했습니다. 나중에 SQL로 옮길 때 맞는지 비교하는 기준으로 씁니다. Spark · 데이터가 24만 행 정도라 나눠서 처리할 필요가 없었습니다.
테스트
Phase 1 · 사용 중		 pytest42개 손으로 계산한 값과 맞는지, 코드를 고친 뒤에도 결과가 그대로인지 매번 확인합니다. unittest · 같은 검사를 입력만 바꿔 여러 번 돌리기는 pytest가 더 편했습니다.
데이터 구조
Phase 1.5 · 사용 중		 메달리온 아키텍처Bronze → Silver → Gold 원본, 정리한 데이터, 분석 결과를 세 층으로 나눴습니다. 층마다 바로 앞 층만 읽기 때문에 문제가 생기면 어디서 틀렸는지 바로 보이고, 그 층부터 다시 만들면 됩니다. (07 참고) 노트북 방식 · 중간 CSV가 30개 넘게 쌓여서 어떤 파일이 어디서 나왔는지 저도 헷갈렸습니다.
저장 형식
Phase 1.5 · 사용 중		 Parquetpyarrow 카드 데이터가 CSV 16.4MB에서 1.4MB로 줄었고, 숫자와 문자 구분이 그대로 남아 다시 읽어도 바뀌지 않습니다. CSV · cp949와 utf-8이 섞여 글자가 깨진 적이 있고, 다시 읽으면 타입이 바뀌기도 했습니다.
수집 · 적재
합성 데이터
Phase 2		 NumPy 생성기시드 고정 공모전 원본은 공개할 수 없어서, 형식과 분포만 비슷한 가짜 데이터를 만들어 누구든 돌려 볼 수 있게 할 계획입니다. 원본 공개 · 재배포가 안 됩니다. Faker · 이름, 주소가 아니라 숫자 분포만 필요합니다.
수집
Phase 2		 requestsKOSIS, NAVER API 인구 데이터를 매번 사이트에서 내려받던 일을 API로 바꿉니다. 실패하면 다시 시도하고, 같은 달을 두 번 받아도 결과가 같게 만듭니다. 수동 다운로드 · 매달 반복하기 어렵고, 어떤 파일을 썼는지 기록이 남지 않았습니다.
원본 보관
Phase 2		 MinIOBronze 저장소, S3 호환 받은 원본을 손대지 않고 달별 폴더에 둡니다. 한 달 데이터에 문제가 생기면 그 달만 다시 돌리면 됩니다. 로컬 폴더 · 클라우드로 옮길 때 코드를 다 바꿔야 합니다. AWS S3 · 개인 프로젝트라 비용이 부담됩니다.

웨어하우스
Phase 3		 PostgreSQLsilver, gold 스키마 Silver와 Gold를 스키마로 나눠 SQL로 관리합니다. 서버형 DB를 직접 설계하고 운영해 보려는 목적도 있습니다. DuckDB · 가볍고 편하지만 권한이나 동시 접속 같은 운영 부분을 다뤄 볼 수 없습니다.
변환
Phase 3		 dbtSQL 모델 Phase 1에서 나눠 둔 함수를 하나씩 SQL 모델로 옮깁니다. 어떤 표가 어디서 왔는지 보여주는 계보 문서와 테스트가 함께 생깁니다. 파이썬 스크립트, 프로시저 · 표가 많아지면 출처와 검사 내용을 따라가기 어렵습니다.
품질 검사
Phase 3		 dbt tests+ 대사 쿼리 빈 값, 이상한 연령대, 없는 지역 코드, 6개월 누락, 원본 합계와 결과 합계를 매번 자동으로 맞춰 봅니다. 눈으로 확인 · 공모전 때 '20대미만'과 '20대이하'가 달라서, 합친 뒤에야 빈칸을 발견했습니다.
운영 · 제공
스케줄링
Phase 4		 Airflow월 배치 DAG 수집부터 대시보드까지 순서대로 돌리고, 실패하면 다시 시도하고, 지난 달을 다시 돌리는 일(backfill)까지 한곳에서 관리합니다. cron · 작업 순서를 정하거나 실패한 지점부터 다시 돌리기가 어렵습니다.
실행 환경
Phase 2~4		 Docker Compose DB, 저장소, Airflow, 대시보드를 명령 하나로 똑같이 띄웁니다. 하나씩 설치 · 버전이 조금만 달라도 "내 컴퓨터에선 되는데"가 생깁니다.
자동 검증
Phase 4		 GitHub ActionsCI 코드를 올릴 때마다 테스트와 전체 실행을 돌려서, 깨진 코드가 main에 들어가지 않게 합니다. Jenkins · 서버를 따로 띄워야 해서, 저장소에 바로 붙는 쪽을 골랐습니다.
조회 화면
Phase 4		 Streamlit Stress, 4유형, 방어형 고객을 파이썬만으로 빠르게 보여줍니다. 이 프로젝트의 중심은 파이프라인이라 화면은 가볍게 가져갑니다. Superset, Tableau · 설치와 설정이 무겁고, BI는 이번 목표가 아닙니다.
보안
계속 · 사용 중		 .env, .gitignore+ 집계 마스킹 API 키는 코드 밖에, 원본과 결과 파일은 저장소 밖에 둡니다. 공개하는 건 집계된 숫자뿐입니다. 코드에 키 작성 · 공모전 노트북을 공개하기 전에 키를 지우는 스크립트를 따로 만들어야 했습니다.
