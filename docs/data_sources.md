# 데이터 출처

이 프로젝트가 쓰는 원본이 어디서 왔고, 어떤 모양이며, 파이프라인의 어디로 들어가는지 정리한 문서입니다.
표 · 열의 자세한 설명은 [데이터 웨어하우스 데이터 사전](warehouse/README.md), 원본마다 부딪힌 형식 문제와 처리 방법은 [기록 07](notes/07_messy_raw_data.md)에 있습니다.

## 확실한 정도 표시

출처를 추측으로 적지 않으려고, 근거에 따라 나눠 표시합니다.

| 표시 | 뜻 |
|---|---|
| **확인** | 제공처와 값을 직접 확인함 (예: API로 다시 받아 파일과 한 칸씩 비교) |
| **형식으로 추정** | 파일의 열 이름 · 구조가 그 기관이 내려주는 형식과 같아 그렇게 봄. 원래 내려받은 곳은 다시 확인 필요 |
| **확인 필요** | 제공처를 아직 확인하지 못함 |

- 2 · 3번은 API로 다시 받은 값이 파일과 서울 2,080칸 · 경기 2,560칸 모두 같았습니다 (2026-10-21, [기록 09](notes/09_api_collection.md)).
- 4번은 KOSIS 검색에서 부산 구 · 군별 표를 찾지 못했습니다. 파일 안에 부산시 내부 작업 시트(`cd1` · `cd2` · 수식)가 남아 있어 부산시가 따로 낸 자료로 보지만, 내려받은 곳은 다시 확인해야 합니다.
- '공개 ○'라도 원본 파일은 저장소에 올리지 않습니다. 저장소에는 [합성 데이터](notes/11_synthetic_data.md)와 발표에 이미 공개한 집계(`contest/results/`)만 있습니다.

## 원본마다

### 1. BC카드 결제

| 항목 | 내용 |
|---|---|
| 파일 | `bc_card_202601_202606.csv` (16.4MB, 242,574행). 다음 달부터는 배치마다 `bc_card_<시작월>_<끝월>.csv` 한 파일씩, 같은 달이 겹치면 늦게 온 파일을 씀 |
| 단위 | 기준년월 × 시도 × 시군구 × 성별 코드 × 연령 코드 × 업종 |
| 열 | `STRD_YYMM, SIDO_NM, CCG_NM, GENDER_CD, AGE_CD, TP_BUZ_NO, TP_BUZ_NM, amt, cnt` |
| 주의할 점 | 성별 코드 `3` · `x`(개인이 아니거나 알 수 없음)가 행의 약 34% · 금액의 13.6%. 업종명 안 공백(`편 의 점`). 경기는 일반구 단위. 6개월이 다 없는 지역 × 업종이 있음. **결제 10건 이하 칸은 제공되지 않음**(가장 작은 칸 11건, dbt 테스트로 확인) |
| 들어가는 곳 | Bronze `card_spending/` → `raw.card_spending` → `silver.silver_card_spending` → Gold 전부 |

### 2 · 3 · 4. 장래인구 (서울 · 경기 · 부산)

| 항목 | 서울 | 경기 | 부산 |
|---|---|---|---|
| 파일 | `seoul_future_population_2022_2042.csv` (2.1MB, 9,048행) | `gyeonggi_future_population_2022_2042.xlsx` (4.2MB) | `busan_future_population_2015_2040.xlsx` (6.5MB) |
| 지역 단위 | 자치구 | 시 · 군 (일반구 없음) | 구 · 군 |
| 연령 표기 | `0~4세`, `0세`, `합계`, 마지막 `90~94세` · `95세 이상` | `0 - 4세` / 연령별(2) `소계` · `0세` | 경기와 같음 |
| 주의할 점 | 5세 · 1세 · 합계 행이 섞임. 9,048번째 줄쯤 닫히지 않은 따옴표 | 병합 셀이라 시군구 · 성별이 블록 첫 행에만 | 경기와 같음. 다른 작업 시트가 함께 있음 |
| 들어가는 곳 | Bronze `future_population/` → `raw.future_population` → `silver.silver_future_population` → `gold_age_stress` | 같음 | 같음 |

- 2026년(기준연도) 대비 2030 · 2035 · 2040년 증감률을 Future Stress에 씁니다.
- 서울 90세 이상 인구는 발표 결과 재현을 위해 지금도 빠져 있습니다 ([리팩토링 노트 4절](refactoring_notes.md)).

### 6 · 7 · 8. 외부 유입 (보정 검증용)

| 항목 | 서울 생활인구 | 부산 생활인구 | 경기 유동인구 |
|---|---|---|---|
| 파일 | `seoul_living_population_2025.csv` (76.4MB, 217,800행) | `busan_living_population_age.xlsx` (1.5MB) | `gyeonggi_flow_202601_202603/` CSV 48개 (24.3MB, 116,928행) |
| 단위 | 자치구 코드 × 날짜 × 시간대, 성별 × 5세(74세까지) | 행정동 × 기준년월 × 나이대 | 시군(일반구) × 시간대 × 내외국인, 성별 × 5세 |
| 주의할 점 | 60대이상이 60 ~ 74세만 | 2025년이 아닌 행 섞임, `20대미만` 표기 | 시군 × 월마다 파일이 따로, 파일명 `연천시` 오타 |
| 쓰는 곳 | 서울 Stress 재가중 (일치율 · Spearman) | 부산 거주 노출 비율 보정 | 경기 Stress 재가중 |

이 셋은 지역마다 기간 · 구조 · 보정 방식이 달라, 각 지역 안에서 '보정 전 vs 후'로만 비교합니다. SQL로 옮길 대상이 아니라서 raw 스키마에는 넣지 않았습니다 ([기록 15](notes/15_postgresql.md)).
